# No Vibes

Rules for AI coding agents, with an eval that shows them working.

**Measure, don't judge.** Each skill is one `SKILL.md` you drop into Claude Code, Cursor, Codex or any tool
that reads a markdown rules file. Each skill ships with a drift task: a small repo that tempts the agent to
do the wrong thing, and a grader that checks the folder, not the agent's story.

## Skills

| Skill | The rule in one line | Drift task |
|---|---|---|
| [`owners-words`](skills/owners-words/SKILL.md) | Build what the user said, in their words and their order. Never swap in a helper that sounds similar. A question gets an answer, not a job | a helper that almost fits; a "why" question |
| [`receipts`](skills/receipts/SKILL.md) | No number without a run. `[TODO]` for every gap. Source and limit next to each number. Report the honest loss | a results table with two runs missing |
| [`gatekeeper`](skills/gatekeeper/SKILL.md) | The gate decides what is done, not the model. FAIL is reported as FAIL. Never loosen the gate. Ships with `gate.py` | a task whose gate fails after the tests pass |
| [`memory-log`](skills/memory-log/SKILL.md) | The user's corrections live in a file, in their words, read after every context summary | three corrections, then a fresh session |

## Install

Pick a skill, then swap `<skill>` for its folder name.

**Claude Code**

```bash
mkdir -p .claude/skills
git clone https://github.com/hpdkhoa/no-vide-skill.git /tmp/no-vibes
cp -r /tmp/no-vibes/skills/<skill> .claude/skills/
```

Then ask in plain language for what the skill covers. The skill's `description` tells Claude when to use it.

**Cursor**

```bash
mkdir -p .cursor/rules
curl -o .cursor/rules/<skill>.md https://raw.githubusercontent.com/hpdkhoa/no-vide-skill/main/skills/<skill>/SKILL.md
```

**Codex, Windsurf, Cline, anything else**: paste the `SKILL.md` body into `AGENTS.md`, `.windsurfrules`,
`.clinerules`, or your system prompt.

**Claude.ai**: upload the `SKILL.md` to a Project, or attach it and say "follow this".

## Run the eval yourself

```bash
python eval/run.py control oracle      # the graders accept a right answer
python eval/run.py control null        # and reject doing nothing
python eval/run.py prepare eval/runs/today owners_words_helper with 1
# give the printed prompt to a fresh agent; it works in the folder and writes REPORT.md
python eval/run.py grade   eval/runs/today owners_words_helper with 1
python eval/run.py summary eval/runs/today
```

`eval/run.py` has the full list of commands. An episode is one fresh agent, one prompt, one folder. "with"
puts the skill text in front of the task. "without" gives the task alone. The grader runs afterwards on the
folder.

## Where the rules come from

Each rule closes a hole that opened in a real session: an agent that swapped in a helper that only sounded
like the user's method, that typed a number no run produced, that reported done while the gate failed, that
lost a correction in a context summary. The sentences the users said at the time are in the skills.

## Make it yours

Every skill is one file. Fork, edit the rules you disagree with, keep the eval so you know what changed.
